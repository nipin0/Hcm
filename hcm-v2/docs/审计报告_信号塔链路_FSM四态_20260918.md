## 4. LightGBM 四态模型使用缺陷（M 组）

### M1 🔴【高·静默】`decided` 只看 top-prob，margin 完全不参与判定 ✅
`state_infer.py:292-302`：`margin=top-second` 算出后**无任何消费点做门控**（全仓确认）。四分类近均匀分布 top≈0.25，`min_conf=0.35` 下 top=0.36/margin=0.033（argmax 由噪声主导）仍 `decided=true`——**0.35 门槛≈无门槛**，唯一过滤只剩 k=2 防抖，而噪声单根直接参与防抖累计。

### M2 🔴【高·静默】单一全局 min_conf，无 per-class 阈值/校准
`state_infer.py:47/114/297`：oscillation（recall 0.14）与 trend_fade（recall 0.79）共用 0.35；无 Platt/isotonic 校准，换模型（v5→v6）后 0.35 语义漂移不可比。

### M3 🔴【高】弱类后果直接传导（LIVE）
`state_machine.py:98-103`（CLASS_TO_STATE）→ 策略层：`oscillation` recall 0.14 支撑 S1/S0 箱体逆势**真实下单**；`trend_fade` recall 0.79 + k_fade=2 ⇒ S4 高吸收 ⇒ 全系统无单。状态分布被弱模型单向绑架。

### M4 🔴【中高】低置信"保持前值"（hold）+ 弱 oscillation ⇒ 趋势出口近乎失效
`state_machine.py:346-349`：undecided 不参与防抖，退出需 k_exit 连续 decided 非趋势；decided 的 oscillation 极少 ⇒ 出口只剩 fade→S4→flat_reset 链；实测漏检 286/误报 92.8%/中位 +1.0 滞后（`:73-82` 注释自证）。与 M3 叠加"易进难出"。

### M5 🟡【中】`predicted_class` 语义混淆
`state_infer.py:298` 无条件 argmax；`state_machine.py:242` 不区分 decided 落库；`:366-367` S2 重映射后 state=S2/predicted_class=trend_mid 并存——replay/评估按 predicted_class 对齐真值会系统性高估模型参与度。

### M6 🟡【中】同一决策两套口径：FSM `decided` 用 top≥0.35，风控 `confidence` 用 margin≥阈值
