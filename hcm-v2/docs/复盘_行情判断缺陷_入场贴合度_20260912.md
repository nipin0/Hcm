> 生成时间：2026-09-12（周六）。时间戳 UTC，上海 = UTC+8。
> **自我纠正声明**：前一份报告（复盘_交易状况_亏损根因_优化_20260912.md）把根因归到"执行端 R:R 坍缩（赚小/亏大）"。那是**表层症状**。本版按用户指正，从**下单点位是否贴合行情**重新审视，结论：根因在**引擎对行情的判断本身有结构性缺陷**——单子就下在了不该下的位置，止盈止损怎么调都改不了 63% 扫 SL。R:R 坍缩只是这些缺陷在账面上的投影。

## 3. 系统"行情判断"的 6 个缺陷（按因果强度）

### 缺陷 A — 方向性结构偏置：做空双通道、做多饥饿（最致命）
HEXP 从**两条独立通道**都能产出 SELL：
- ① TREND 体制"顺势做空下跌"（因子 ma/mm/di_minus 判空 → dir_sum 负 → SELL）；
- ② TREND_FADE 体制"逆势摸顶"（MACD/RSI 高位 → 反转 SELL）。

做多却只有：① TREND"顺势做多上涨"；② 极值护栏 `rsi_launch_low<35` 超卖 launch。

**证据**：信号层 20 个里 19 SELL / 1 BUY（`388644673`），与持仓 34/2 一致。`388644531` 因子 `dir_sum=+0.308`（判涨）却被 TREND_FADE 反转为 `verdict=-0.6`→SELL（indicator_values）。做多侧在"下跌段"被 TREND 体制判 SELL、在"超卖段"需 rsi<35 才 launch，二者冲突 → 做多几乎不触发。
→ 结果：上行市里只做空，等于先天站错边。

### 缺陷 B — 高周期滞后趋势分锚定 → 逆主趋势摸顶（12:36/12:52 灾难根源）
HEXP 方向 `verdict` 由 D1/H1/H4/M5/M30 加权共识算出（`hexp_engine.py:1620-1706`），且**方案 B 已取消 verdict 的"否决动作"，仅调分不拦截**（`:119` `verdict 仅取消"否决动作"`）。09-11 白盘 D1/H1/H4 趋势分全 <40（滞后反映早盘跌势），却压着 M5 创高的价格连续 SELL。

**证据**：`388644596`（12:36 入 4351）`pos_in_range=0.973`（近 20 根区间顶）、`rsi=61.6`、`adx=29.7` 上涨段，但 `trend_scores` D1=36.9/H1=29.2/H4=24.2/M5=10.4 全低 → `verdict=-0.6` SELL。价格随后创高到 4400，无认错机制 → −19.8。`388644600`（12:52 入 4379）`pos=0.959`、`rsi=74.7` 超买，同样 `verdict=-0.6` SELL → −20.9。
→ 引擎的"共识"锚定在过时高周期，对实时极端位置失明。

### 缺陷 C — 极值护栏（extreme_guard）对"顺势追跌底部"失效（03:58 灾难根源）
护栏设计（`hexp_engine.py` 注释 + 配置）"**顶部只拦 BUY 追顶、底部只拦 SELL 续跌追底**"。但 03:58 那笔是 **TREND 体制"顺势追跌"**，护栏只拦"反转摸底"不拦"顺势追跌"，两种都做空在低位 → 放行。

**证据**：`388644517`（03:58 入 4302）`pos_in_range=0.056`（近底）、`rsi=31.1` 超卖、`ma=0`/`mm=-0.48` 下跌 → TREND 体制顺势 SELL 放行。遇亚盘跳空上冲，SL 被桥接从信号 4306（≈0.7ATR）**改宽到 4342（≈7ATR）** → −39.78。
→ 护栏留了"顺跌追底"的口子，正好踩中崩盘底+跳空。

### 缺陷 D — RED 安全栅栏 09-11 未生效（低质信号进实盘）
配置明示"**RED 恒不可交易**"（`hexp_engine.py:415` `全局安全栅栏（RED 恒不可交易）`、`:435` `RED 恒不可交易`），`hexp.min_grade=C`（`:206`），精确信号闸门 step9（`:1928-1932`）只放行 ≥min_grade。但 09-11 有 RED 级信号对应持仓真实成交并亏损。

**证据**：`388644551`(09:28,grade RED,−2.5)、`388644570`(11:00,RED,+3.7)、`388644572`(11:16,RED,+1.3) 三笔 `_hexp.grade=RED` 却 `direction=SELL` 且 `hcm_trading.positions` 确有对应成交。结合 `quality_gate.py:284`（`if not enabled or mode!="coupled" ...` early-return）→ 09-11 `ai.mode=decoupled` 时 AI 闸门整体 passthrough，唯一过滤是 HEXP 自身 `passed`；RED 仍被放行 → **疑似 `regime_min_grade` 覆盖或 bridge 未读 `passed`**，需核实。

### 缺陷 E — 行情判断与风控解耦：能判"买点好坏"的模块被雪藏、SL/TP 任意改宽（R:R 坍缩的真源头）
- `precision_entry.py`（Layer 2 "精准买点分"）本应评估**方向对齐度 + 微观结构 + R:R 位置**，且内部 `_risk_reward` 设计 SL=1.0ATR、TP=1.5ATR（R:R 1.5，`min_rr=1.2` 硬门槛）。但文件头明写 **"Phase 0 仅 shadow 模式：本模块从不改变交易行为"**（`:6-8`）→ 该模块**不在实盘链路**，只算分不拦截。
- 所有 `hcm_signal.signals` 的 `sl_price=0`、`risk_ratio=0`、`lot=0` → SL/TP 由桥接在信号之后另算。桥接可任意改宽 SL（见缺陷 C 的 0.7ATR→7ATR）。
- 实际 SL 距 0.4ATR（03:30）~7ATR（03:58）无一致逻辑；设计 R:R 2.15 是桥接数学的偶然产物，非引擎控制。

→ **上一版所谓"执行端 R:R 坍缩"，根因在行情判断层完全不约束风险控制**：没有模块在入场时验证"这个买点 R:R 够不够、方向贴不贴合"。

### 缺陷 F — 趋势护栏是"软参考"，且唯一硬拦只能抓"共识相反"、抓不住"共识本身错"
- `hexp.trend_priority_mode: "shadow"`（配置）→ 趋势优先只是软参考，不硬拦逆势单。
- `counter_block`（`hexp_engine.py:1733-1766`）仅当 `|verdict|≥0.5 且方向与共识相反` 才 NO_TRADE。当共识本身错（如 12:36 共识也判 SELL 却撞上创高）时，方向与共识同向 → **不触发**，无更高 authority 拦截（mtf veto 已被方案 B 取消，见缺陷 B）。

## 5. 修正后的优化杠杆（按"行情判断修复"优先重排）

> 全部为参数/逻辑改动，按铁律需逐项授权。建议从杠杆①（零代码、当日可回测）起步。

**① 把 `precision_entry` 从 shadow 接进实盘（最直接补"买点贴合度"）** — `precision_entry.py:6-8` 改为生效；其 `min_rr=1.2` 硬门槛 + 方向对齐 + 微观结构(TREND_PULLBACK/REVERSAL) 直接在信号层拦截"不贴合行情"的入场。这是已被写好却雪藏的模块。

**② 修方向偏置（缺陷 A）** — 解锁做多侧对称性：超卖 launch(`rsi_launch_low`) 不应被 TREND 顺跌覆盖；或加"单日净方向敞口上限"防止 34/2 类单边。

**③ 高周期趋势分加衰减/确认（缺陷 B/F）** — D1/H1/H4 趋势分在 regime 翻转时滞后，应加衰减窗口或要求 M5 实时极值(pos_in_range/rsi)与共识同向才放 TREND_FADE 摸顶；TREND_FADE 加"趋势延伸 N 根未反转则认错平仓"。

**④ 极值护栏覆盖"顺势追跌底部"（缺陷 C）** — 不仅拦"反转摸底"，也拦"顺跌追底"（pos_in_range 近底 + di_minus 高位时禁止 SELL）；周五/低流动性时段降手数或禁新单缓 jump。

**⑤ RED 栅栏生效核查（缺陷 D）** — 核实 `regime_min_grade` 是否覆盖全局 RED 栅栏；bridge 必须读 HEXP `passed`，RED/未过闸信号一律不下单。

**⑥ SL/TP 由引擎统一按 ATR 倍数下发（缺陷 E）** — 禁 bridge 任意改宽 SL；接入 precision_entry 的 1.0/1.5 ATR 方案，使设计 R:R 可控、可审计。
