## 1. B15-3 · `hold_only` 被"同态"错误清除，停止加仓仅维持一根

**改动文件**：`hcm-signal-tower/signal_tower/state_machine.py`（`:368-374`）

**根因（已核实）**
```python
# 7) 同态：清零待迁计数
if target == cur:
    st.pending_class = ""
    st.pending_streak = 0
    if cur in (MarketState.S2_TREND_INIT, MarketState.S3_TREND_MID):
        st.hold_only = False          # ← 缺陷：同态即解除"停止加仓"
    return _keep("same_state")
```
`:376-382` 在"趋势态下转震荡且仍有持仓"时置 `hold_only=True`（规格 10.2）。但**下一根只要模型再判同一趋势态**（`target == cur`），第 7 步立刻把 `hold_only` 清掉 ⇒ **"停止加仓"只生效一根 bar**，S3 加仓逻辑随后照常运行。

**危害**：规格 10.2「转震荡 → 停止加仓、持仓保留」形同虚设；在"模型在趋势/震荡间抖动"的行情下，实际持续加仓。

**方案（建议语义，需你确认）**
1. **删除**第 7 步中的 `st.hold_only = False`。
2. `hold_only` 仅在以下两种情形清除：
   - **(a) 无持仓**（`positions_open == 0`）：`hold_only` 的语义前提（"持仓保留"）已不存在；
   - **(b) 趋势态经"确认"重新进入**：即第 8.5 步的 `require_trigger` + `direction` 两道门**通过**时清除（`trigger_enter` 路径 `:303` 已有清除，保留不动）。
3. **上界兜底（可选，防永久停止加仓）**：新增 `state.hold_only_max_bars`（默认 12，对齐 `state.horizon_bars`）——`hold_only` 连续为真超上限 → 强制清除 + WARNING。

**影响面**｜加仓频率下降（符合规格原意）；若模型长期判趋势而现实中已转震荡，则"停止加仓"会持续更久 ⇒ 收益/风险均需观察。
**回归基线**｜① `market_state_log` 中 `hold_only` 为真的 bar 占比（改前/改后）；② `mid_add_on_pullback` 与 `mid_max_adds_reached` 计数；③ `same_state` note 下的 `hold_only` 取值分布。
**回滚**｜`git checkout hcm-signal-tower/signal_tower/state_machine.py` + `docker restart hcm-v2-hcm-signal-tower-1`。
**待确认**｜(1) 上述语义 (a)+(b) 是否即为你要的规格？(2) 是否要 (3) 的 N 根上界，N 取多少？

## 4. C4 · 4ATR 预算清锁块位于贴边 `return` 之后 ⇒ S0/S5 场景不可达

**改动文件**：`hcm-signal-tower/signal_tower/state_strategy.py`（`:1286-1328` 抽函数并前移调用点）

**根因（已核实）**

⇒ 只要**未贴边**（`osc_edge_wait` / `osc_outside_box` / `osc_inside_box` 三类，即绝大多数 bar），即使 `osc_atr_loss ≥ limit` 且**已无持仓**，**清锁也不执行** ⇒ `osc_atr_loss` / `osc_loss_count` **只增不减**（缺陷 B：手数档位长期顶格）。S0/S5 场景尤其不可达。

3. `:1320-1328` 的"**有持仓 ⇒ 不出新箱体单**"（封堵）**保留原位不动** —— 它依赖贴边上下文，只在贴边处才有意义。

**影响面**｜清锁更及时 ⇒ 手数梯度更频繁回到第一档（**这正是规格 9.4 的原意**，也是"新轮首单直接 0.03"的另一半修复）；风险 = 若"无持仓"判定有误（持仓计数延迟），会提前清掉预算 → 需观察清锁日志频次与 `osc_atr_locked_no_new_order`。
**回归基线**｜① 清锁 WARNING 日志的出现位置（应不再被贴边 return 挡住）；② `osc_atr_loss` / `osc_loss_count` 是否在 S0 平完后归零；③ 新箱体单 `lot_multiplier` 是否回到第一档；④ S5 锁止次数（不应激增）。

2. 增加**可观测**：`-1` 时每 bar 打 WARNING（含 symbol/state/`_fsm_pos`），便于统计揭示率。
3. **不做**重构式"以 `positions` 表计数为真源"（现有 `_count_fsm_open_positions` 已是该设计，报告原方案属重复建设）。

**风险控制（建议两段式）**｜先只上 (1)+(2) 观察一周；若日志显示 `-1` 频次高或出现持仓数 > `max_adds+1`，再补硬闸（`-1` 连续 N 根 ⇒ 直接不出加仓单）。
**回归基线**｜① `fsm_adds_used=-1` 出现频次（新增 WARNING 可统计）；② `mid_add_on_pullback` vs `mid_max_adds_reached` 计数；③ 同轮最大实际持仓笔数是否 ≤ `max_adds+1`。
