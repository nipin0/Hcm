# 机制深析：为何"上涨中做空被打损、反转后却不空"

> 2026-09-12（周六）。回答用户追问：系统为什么在 buy 行情下 sell 后被止损，而行情反向（转跌）时却不下 sell 单？  
> 结论先行：**HEXP 本质是一个"滞后多周期共识 + 均值回归（摸顶抄底）"引擎，不是趋势引擎。它的 SELL 只来自"强势/高位"的回调逻辑，BUY 只来自"弱势/低位"的回调逻辑；当行情真转跌时，它既没切换到趋势跟随做空，又用均值回归去抄底——于是永远站在错误一边。**

→ **全天引擎从未识别出"下跌趋势"**，所以"趋势跟随做空"这条唯一能在跌市盈利的路径从未打开。

## 2. 形成机制（分步，配 file:line）

### 2.1 HEXP 是均值回归引擎，不是趋势引擎

配置注释（`hexp_engine.py:49-50`）：原趋势组权重过高导致"NEUTRAL 高位只追趋势多、不反向"，已**刻意调成 NEUTRAL 高位自然偏向反向（做空）**。即设计目标就是"涨多了卖、跌多了买"的回调策略，而非"顺势跟"。

### 2.2 SELL 的两个来源都在"强势/高位" → 上涨中做空

- **NEUTRAL-fade（38 笔 SELL 的主力）**：价格处区间高位/RSI 偏高 → 反向 SELL（摸顶）。`388644531` 因子 `dir_sum=+0.308`（判涨）却被 TREND_FADE 反转为 `verdict=-0.6`→SELL（`indicator_values`）。
- **TREND 体制 SELL（14 笔）**：仅在"主周期状态机确认趋势"时顺势。但 09-11 白盘价格总体上行，TREND 体制把"上行"判为可跟 → 顺势做空（其实是摸续涨段），遇趋势延伸被打（12:36/12:52，−19.8/−20.9）。

→ **上涨市里，NEUTRAL-fade 与 TREND 都产出 SELL**，且都基于"当前价格强"的判断 → 自然在涨中做空、被打损。

### 2.3 行情反向（转跌）后：均值回归逻辑=做多（抄底），且趋势跟随做空被卡死

反转后价格从 4400 回落，进入"弱势/低位"：

- **NEUTRAL-fade 在跌市 = BUY**：价格跌 → "跌多了买"（抄底）。证据：17:15 `388644673` BUY（NEUTRAL，`pos_in_range=0.545`、`rsi=50.5`、`dir_sum=+0.132`）——峰值回落后第一反应就是抄底多，亏损 −9.2。
- **TREND_DOWN 体制从未触发**（全天 0 笔）：趋势跟随做空路径要求 regime 翻成 `TREND_DOWN`，但：
  - `hexp.trend_priority_mode: "shadow"`（`hexp_engine.py:328`）→ 趋势优先只是软参考，不硬承诺做空；
  - 趋势启动门槛偏高：`hexp.trend_start.bbw_max=20`、`donchian_look=10`、`h1_ema=50`、`hold_bars=90`（`hexp_engine.py:339-342`）→ 09-11 午后那波回落未满足"持续 90 根 + H1 EMA + Donchian 突破"等硬条件，regime 卡在 NEUTRAL；
  - 反转窗口 TREND 体制 11 笔**全 NO_TRADE**：`hexp_engine.py:1556`「逆势方向，在状态机确认趋势 TREND_UP/DOWN 时收口为 NO_TRADE」——当检测到的趋势方向与候选方向相反时直接收口，而午后多空拉扯中 `dir_sum` 近 0 或被 `counter_block` 拦 → 既没出 BUY 也没出 SELL。

→ **转跌后，引擎只有"抄底多"（NEUTRAL/RANGE BUY）和"被收口无单"，没有任何做空产出**——正是"行情反向却不下 sell 单"。

### 2.4 多周期共识滞后：引擎永远在交易"上一根腿"

方向 `verdict` 由 D1/H1/H4/M5/M30 加权（`hexp_engine.py:1620-1706`）。高周期（D1/H1/H4）滞后于 M5 实时价格：

- 12:36 涨中：`trend_scores` D1=36.9/H1=29.2/H4=24.2/M5=10.4 全低（熊共识滞后）→ `verdict=-0.6` SELL，撞上创高 4400 → 损。
- 17:15 反转初：`trend_scores` D1=35.86/H1=29.75/H4=34.42 仍低位（熊共识仍滞后反映早盘跌势 / 尚未翻多）→ 但信号走 NEUTRAL-fade BUY（抄底）。

即：**高周期共识比 M5 价格慢 1~2 段**。涨时它还在说"跌"→ 催出 SELL（撞涨）；刚转跌时它还在说"涨/平"→ 催出 BUY（抄底）。引擎始终在与"刚过去的腿"反着做，从不在"当下的腿"上顺势。

### 2.5 唯一的方向安全网也抓不住

`counter_block`（`hexp_engine.py:1733-1766`）仅当 `|verdict|≥0.5 且方向与共识相反` 才 NO_TRADE。当共识本身错（如 12:36 共识也判 SELL 却撞创高），方向与共识同向 → **不触发**；且方案 B 已取消 mtf verdict 的否决动作（`hexp_engine.py:119`），无更高 authority 纠正错误共识。

## 3. 闭环对照（同一天的三个时间点）

| 时间    | 行情             | 引擎动作                         | 结果    | 机制                        |
| ----- | -------------- | ---------------------------- | ----- | ------------------------- |
| 12:36 | 涨中创高 4351→4400 | NEUTRAL/TREND SELL（38/14 主力） | −19.8 | 2.2 涨中做空 + 2.4 滞后共识催空     |
| 17:15 | 峰值回落后          | NEUTRAL BUY（抄底）              | −9.2  | 2.3 转跌→均值回归做多             |
| 18:50 | 继续回落           | NEUTRAL SELL（滞后、小损）          | −3.4  | 2.3 趋势做空路径仍关，只剩晚到的 fade 空 |

**同一波"涨→顶→跌"，引擎在涨段空（损）、顶后多（损）、跌段迟到空（小损）——全程没在正确位置做空。**

---

## 4. 一句话根因

> HEXP 的 SELL 来自"强势回调/摸顶"、BUY 来自"弱势回调/抄底"，且方向共识被滞后高周期绑架；因此**涨时它做空（错）、刚转跌它抄底（错）、趋势跟随做空因 regime 软参考+高门槛从未开启**——系统结构上无法在下跌中及时做空，只能在做空中挨打。

对应前版缺陷：A（方向偏置）是表象，本机制是 A 的**时间不对称内核**；B（高周期滞后）是 2.4 的根源；E（precision_entry 雪藏）意味着本可 intercept"转跌抄底多/涨中摸顶空"的模块没接实盘；F（趋势护栏软参考）是 2.3 卡死趋势做空的直接原因。

---

## 5. 修复指向（治本，需逐项授权）

1. **接 `precision_entry` 进实盘**（缺陷 E）：其微观结构状态机含 `TREND_PULLBACK`/`TREND_ACCEL`/`REVERSAL`/`TREND_EXHAUST`，可识别"趋势启动 vs 衰竭"，在信号层拦掉"涨中摸顶空"与"转跌抄底多"。
2. **解锁趋势跟随做空**：`trend_priority_mode` 由 `shadow` 升为有效硬承诺；下调 `trend_start` 门槛（hold_bars/bbw_max/h1_ema）使日内跌势能被识别为 TREND_DOWN 并产出 SELL。
3. **降高周期滞后权重**（缺陷 B）：缩短 D1/H1/H4 在 `verdict` 的衰减窗口，或要求 M5 实时极值（pos_in_range/rsi）与共识同向才放趋势单。
4. **逆势收口对称化**：`hexp_engine.py:1556` 当前只收口"逆势单"；应改为"确认 TREND_DOWN 时强制 SELL（而非仅收口 BUY）"，避免转跌时空窗。
5. **regime 翻转加速**：当价格突破 Donchian + ADX 抬升时，允许从 NEUTRAL 直接跳 TREND_DOWN，不必等 90 根 hold。
