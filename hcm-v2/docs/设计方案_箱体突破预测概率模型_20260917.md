## 0. 需求对齐（铁律十四：先确认需求，再评估）

### 0.1 用户需求（本次任务）
> 实现「**未来 N 根内是否破箱、方向、概率**」，即**直接预测破箱概率 + 方向 + 置信**的推理模型。

### 0.2 所给方案的实际目标
> §2 链路末端：`时序预测模型 → 输出未来20根K线OHLC序列`；
> §3 选型：`LightGBM 多目标回归模型，输出 T+1~T+20 共20根K线 OHLC`。

### 0.3 ★核心结论：**目标错配（必须先纠正，否则做出来不是要的东西）**

| 维度 | 你的需求 | 所给方案 |
|---|---|---|
| 任务类型 | **事件分类**（破 / 不破 + 方向） | **多目标回归**（40~80 个连续值） |
| 输出 | 概率 + 方向 + 置信 | 未来 20 根 OHLC 数值序列 |
| 与「概率」的关系 | 概率是**直接输出**（分类概率 + 校准） | 序列**不直接给概率**，需二次加工 |
| 误差特性 | 单点判断，无累积 | T+15~T+20 **误差累积**（方案 §5.1 自认） |
| 可落地性 | 高（仓库已有同类范式） | 低（远期序列不可用，方案 §5.2 自认"仅作推演参考"） |

> **一句话**：你给的方案是「画未来的 K 线」，你要的是「未来会不会破箱、往哪破、几成把握」。
> 前者是更难、更不可用、且不对口的路；后者是更简单、可校准、且**本仓库已经有人跑通过**的路。
> 本方案评估的结论是：**不建议按原方案实施；建议按第 4 节重构后实施。**

## 1. 结论速览（TL;DR）

1. **原方案"能实现吗"**：技术上能写出"预测 20 根 OHLC 的回归模型"，但——
   - 它**不回答**你的问题（破箱概率/方向/置信）；
   - 远期序列误差累积（方案自己也承认），产出的远期 K 线**不可用于决策**；
   - 用回归去逼近一个**本质是分类**的问题，是绕远路，且**无法给出可信概率**（回归输出的"置信区间"与分类概率不是一回事）。
2. **正确做法**：把任务定义为「**在 bar T 收盘时，未来 (T, T+N] 内是否发生"箱体突破"事件；若破，向上还是向下；校准后的概率是多少**」。
3. **可行性有强证据（不是空想）**：本仓库**已有两条完全同构的成功先例**——
   - `tools/train_onset_model.py`（未来 L 根内是否出现**趋势起点**）：可探测提前量上限 ≈ **20 bar**，L=5 时 OOF **AUC=0.7599**（`train_onset_model.py:3-6`）；
   - `tools/build_state_labels.py:80-89` 的 `vol_expansion`（未来窗口振幅/ATR ≥ 3.13）：OOF **AUC=0.6460**，单特征 `atr_14` 仅 0.5732。
   ⇒ 「未来 N 根内是否发生某事件」这类任务在本仓库**已被验证可做**，且有现成方法论与工具（`tools/eval_anticipation_bound.py`）。
4. **最大风险不是模型，是"事件定义"**：`train_onset_model.py:52-65` 记录了反面教训——onset 初版正例率 **94.9%**，事件退化为常态 ⇒ 模型 P 恒 1、阈值落到 0.99984、生产触发率仅 **0.825%**。**破箱预测若不先把正例率压到 10%~30%，会重演同一失败**。
5. **落地定位**：本模型最有价值的用途是**在 S1 箱体单"贴边开仓"前做前瞻否决/降级**（对应已知缺陷：边沿逆势开仓→破界止损）。但按铁律 5.1（AI 只有否决/升降级权、无独立开仓权），**接入决策必须先出变更说明待确认**；本期先做**离线 + 影子观测**，零实盘风险。

## 4. 优化方案（推荐落地路线）

### 4.1 任务重构：从"序列回归"改为"事件分类"

**定义（建议口径，待用户确认 §7）**：
- **决策点**：bar `T` **收盘**（M5）。
- **参照箱**：
  - 有活跃箱体轮次 → 用**冻结箱**（`box_frozen=True` 的快照三线）；
  - 无轮次 → 用 `T` 时点的**滚动箱**（`compute_entry_box(high[:T+1], ...)`，与生产同函数）。
- **事件**：未来 `(T, T+N]` 内，首次出现「**连续 K 根收盘越界**」（`K = osc.break_confirm_bars = 2`，与生产一致）。
- **输出（三件套）**：
  1. `P_break`：未来 N 根内破箱概率（**校准后**）；
  2. `direction`：`UP` / `DOWN` / `NONE`；
  3. `confidence`：校准概率 + 该 lead 的历史可靠性（分档命中率）。
- **可选**：`E[破箱时间]`（hazard / 第几根破），非必需，二期再议。

**建模形式（推荐 A）**：
- **A（推荐）双二分类头**：`P_up`（上破）、`P_dn`（下破），**允许同时为真**（高波动下可能先下破后上破）。
  派生：`P_break = 1-(1-P_up)(1-P_dn)`（近似）或单独加一个 `P_any` 头；`direction = argmax`。
- **B（更简）三分类**：`up / down / none`（互斥），softmax 概率。
- **选择依据**：先测"上破与下破是否强互斥"（同一窗口内是否常同时发生）——若不互斥，选 A；若几乎互斥，B 更省。**该判断用数据做，不预猜。**

### 4.2 标签构造（复用 > 新写，防泄露）

1. **复用现有工程**：`compute_entry_box`（箱体）+ `osc.break_confirm_bars`（破界判定）——**禁止另写一份箱体/破箱实现**（铁律十三·反冗余）。
2. **特征/标签隔离**（硬约束）：
   - 特征：bar `T` 及之前（复用 `state_features.compute_features_at`，其本身只用 `<=i`，`state_features.py:258`）；
   - 标签：仅 `(T, T+N]`；
   - **样本边界**：一段数据的末尾 N 根必须丢弃（否则越界/泄露），同 `train_onset_model.py:12-13`。
3. **正例率标定（第一道门）**：
   - 扫 `N ∈ {4, 6, 12, 20}`，统计 `P(破箱)` 基准率；
   - **目标 10%~30%**（同 onset 标定口径，`train_onset_model.py:65`）；
   - 若过高 ⇒ 收窄事件（如要求"破界幅度 ≥ x·ATR"或"破界后维持 ≥ K' 根"）或缩短 N；**这是设计动作，不是调参**。
4. **排除"已破"样本**：`T` 时点已在箱外（`box_break_up/dn` 为真）的 bar 不入样本（否则等于白送）。

### 4.3 特征设计（最大化复用，最小化新增）

**直接复用（零新增）**：`STATE_FEATURE_COLS` 27 维（已含 `box_upper_dist_atr / box_lower_dist_atr / box_width_atr / box_dev / close_pctile / box_break_up / box_break_dn / atr_* / adx / r2_linreg / roc_mom / …`）。

**建议新增（箱体方向专属，若消融证明有增益才保留）**：

| 特征 | 含义 | 理由 |
|---|---|---|
| `dist_to_upper_atr` / `dist_to_lower_atr` | 现价到冻结箱上/下沿距离（ATR 归一，含符号） | 决定"哪边更近、更可能先破" |
| `box_width_pctile` | 箱宽在历史分布中的分位 | 窄箱更易破（压缩→扩张） |
| `bbw_pctile / bbw_slope` | 布林带宽分位与斜率 | **挤压（squeeze）** 是突破的前兆；`bbw_pct` 已是质量头特征 |
| `edge_touch_cnt` | 最近 w 根内触上/下沿次数 | 反复触边 → 边界失效概率上升 |
| `hold_time_bars` | 本轮已持续 bar 数 | 箱体寿命（久盘易变） |
| `k_upper/k_lower` | 最近 K 根收盘越界计数（连续 streak） | 直接刻画"破界进行度" |
| `mtf_resonance` | 多周期方向共振（H1/H4/D1） | 仓库已有 `verdict`/`h1_trend_dir` 现成实现（`quality_features.py:478/515`） |
| 时段 | `session_eu/session_us` | 已有 |

> ⚠️ 新增特征必须走**消融验证**（`build_state_labels.py:85-87` 的做法：同一特征集换目标比 AUC），**不得凭直觉堆砌**。

### 4.4 模型与校准（同现有三头栈）

- 模型：**LightGBM 二/三分类**，时序 OOF（`TimeSeriesSplit(5)`，同 `train_signal_quality.py:611`），**多 seed 集成**（同 `train_onset_model`）。
- 阈值：按 **OOF 最大 F1** 或 **目标触发率**标定（`train_onset_model.pick_threshold`，`train_onset_model.py:119-140`）。
- 校准：**Isotonic / Platt**，复用 `NumpyCalibrator`（`calib_np.py`）与退化护栏（`train_signal_quality.py:183-194`）。
- 契约：模型 `feature_name_` fail-fast 校验（`train_signal_quality.py:550-558`）。
- 产物：模型原生 `.txt` + 校准器 pickle（**与现状一致**，不要按原方案"禁用 pickle"）。

### 4.5 上线评估门（先测上限，再建模型 —— 顺序不可颠倒）

**第 0 步（必做）**：用 `eval_anticipation_bound.py` 的方法**扫 L 测信息上限**（换成破箱事件）。
判读（同 `eval_anticipation_bound.py:13-16`）：

| 结果 | 含义 | 行动 |
|---|---|---|
| 所有 L 的 AUC ≈ 0.5 | 信息**不存在** | **停止**，调模型无用（省下全部开发成本） |
| 存在 L 使 AUC 明显 > 0.5 | 信息存在 | 取"最早可探测 L"作为 N 的设计区间 |

**上线判据（建议）**：

| 指标 | 门槛 | 说明 |
|---|---|---|
| OOF AUC | ≥ **0.58**（仓库既有门槛，`eval_anticipation_bound.py:72`） | 低于此视为不可探测 |
| PR-AUC | 显著高于基准正例率 | 类别不平衡下比 AUC 更实 |
| Brier / 校准曲线 | 校准良好（分档命中率单调） | "置信"必须可信 |
| 方向对称性 | 上破/下破 AUC 不得一边倒 | 防止"恒判上破"（历史上已发生过单向偏多问题） |
| 基线对照 | 至少对齐 `vol_expansion` 的 **0.646** | 低于同类目标 ⇒ 无边际 |

> **不做完第 0 步不开工建模**——这是本项目"先审计后提案"铁律的直接应用。

## 7. 待用户确认的问题（铁律十四 · 开工前必须拍板）

1. **参照箱体**：只预测**活跃箱体轮次（冻结箱）**的突破，还是**任意 bar 的滚动箱**？（二者口径不同）
2. **破界口径**：沿用生产「**连续 2 根收盘越界**」，还是改"触及/影线越界"？（后者正例率会很高，易退化）
3. **N 的取值**：固定 N（如 12）还是扫 `N ∈ {4,6,12,20}` 并各自出模型？
4. **交付形态**：`P(破) + 方向 + 置信` 三件套是否足够？是否还要**预期破箱时间**（第几根破）？
5. **落地范围**：本期只做**离线 + 影子观测**（零风险），还是直接规划接入 S1 箱体单的**前瞻否决/降级**（需变更说明）？
6. **方向口径**：是否需要区分"**真突破**（破界后延续）与"**假破**（破界后回箱）"？若要，事件需加"破界后维持 ≥ K' 根"条件。
