## 2. 第 4 项设计：状态去抖 `k_*`

### 2.1 机制（读码）

`state_machine.decide()` 第 482–497 行：`pending_class/pending_streak` 计数，
`need` = `k_fade`（→S4）/ `k_exit`（趋势→S1）/ 否则 `k_enter`；达到即迁移。
参数经 `load_config` 每 30s 热载（`get_float`）⇒ **改配置即可，无需改码/重启**。

### 2.2 离线复算（唯一判据）

用现成沙盘 `tools/replay_state_chain.py`（**调用线上同一批模块**，不复制规则）：

```
python tools/replay_state_chain.py --symbol XAUUSD --tf M5 --since 2026-09-01 \
    --k-enter 2 --k-exit 2 --k-fade 2 --tag k2 --require-trigger <现网值>
python tools/replay_state_chain.py ... --k-enter 3 --k-exit 3 --k-fade 3 --tag k3
python tools/replay_state_chain.py ... --k-enter 4 --k-exit 3 --k-fade 3 --tag k4
```

对照项（脚本原生输出，无需另写指标）：**状态迁移次数**、状态占比、意图 reason 分布、
模拟成交笔数/胜率/均值 R、分状态 R、验收口径（漏检/误报/中位提前量）、`[A/B 摘要]` 行。

### 2.3 判据与风险

- **收益**：迁移次数显著下降（目标 <½）、S0↔S4 横跳链消失、模拟均值 R 不劣化。
- **代价（须诚实计入）**：去抖 = 延迟进入 ⇒ 验收口径的"中位提前量"变差 1~2 根 bar
  （起点越晚，趋势段吃到越少）。故**不接受**"只看 R 不看提前量"。
- **结论取值**：以上三档里选"迁移↓最多且提前量恶化 ≤1 根"的那档；若 k=3 已使提前量劣化 >1 根，
  则只提 `k_enter`（对 S2/S3 生效）而**不动 `k_fade`**（S4 本就不下单，去抖它只影响"何时允许离开 S4"）。

### 2.4 实施与回滚

```
set_cfg.py state.debounce.k_exit 3
```

## 3. 第 5 项设计：触发门重标定

### 3.1 根因（**上游脚本已自证**，`tools/train_onset_model.py:53-59` 原文）

> 实测线上 `lgbm_onset_M5_v1` 的 `train_pos_rate = 0.9493` —— 即"未来 5 根内出现起点"在震荡 bar
> 上有 **94.9% 为真** ⇒ 事件不再是"事件"而是"常态" ⇒ 任务退化：
> · 模型 P(onset) 被压成恒 1（p50=0.9996 / p90=0.9999）；
> · 标定阈值落到 **0.99984**，毫无判别力；
> · 生产 `rise_thr=0.2948` 下 ΔP 触发率仅 **0.825%**（按目标 10% 标定应为 **0.002301**）
>   ⇒ **趋势入口事实上关闭**（全历史 `trigger_on = 1/363 = 0.28%`）。

**与昨日实测完全吻合**：40 次触发的 reason 全为 `donchian`，`rise` 分支 0 次 ⇒ 判据同源。

### 3.2 设计（三步，依次）

1. **重建起点事件**（去退化）：`train_onset_model.py --min-quiet N --min-run M`
   —— 只取"当前已连续震荡 ≥N 根"的 bar 作为样本、只把"其后趋势段连续 ≥M 根"的上升沿计为事件。
   目标：`train_pos_rate` 从 0.95 降到 **0.2~0.4**（事件稀有化）。N/M 由 §3.3 的网格定。
2. **重标 `rise_thr`**：用 `trend_trigger.calibrate_rise_thr(oof, m, on_rate=0.10)`
   （**按目标触发率分位**，不用最大 F1 —— 纪律见 `trend_trigger.py:19-20`）⇒ 写入配置。
3. **重估 `donchian_w` 与 `required`**：用 `replay_state_chain.py --require-trigger 0/1` 与
   `--cfg state.trigger.donchian_w=<w>` 做 A/B；判据 = 触发的**前视边际 ≥ 未触发**（当前是反向的）。

### 3.3 验收标准（不达标不上线）

- `trigger_on` 比率从 0.28% 提升到 **≈10%**（目标分位），且 `rise` 分支**非零**触发；
- 触发子集的**前视边际 > 未触发子集**（今日实测：+4.19 vs +11.01，必须翻转）；
- 验收口径"中位提前量 ≤ 0"（不劣于 `donchian` 基线的 0.0）；
- 无非法迁移增加（不变式 I1）。

### 3.4 风险与回滚

- **自动晋升风险**：`state_infer._discover()` 取 `max(version)` ⇒ **放入 v2 文件即被线上加载**。
  故：训练输出到 `tools/_scratch/onset_v2/` **先验证**，通过后才 `tools/models/`；
  回滚 = 移除 `lgbm_onset_M5_v2_*`（秒级，回退到 v1）。
- `rise_thr` 配置回滚 = `set_cfg.py state.trigger.rise_thr 0.2948`。

## 4. 第 6 项设计：4 类模型类别不平衡（**先诊断，后改**）

### 4.1 已知事实（读码，修正了一个常见误判）

`train_state_model.py:89-96` 的 `class_weights()` **已用 `sklearn.compute_class_weight("balanced")`**
并叠加 `CLASS_WEIGHT_BOOST_DEFAULT = {oscillation 1.0, trend_init 1.0, trend_mid 1.0, trend_fade 1.5}`
⇒ **"没加类别权重"不是根因**。故必须先用判据脚本区分两类病因：

- **(a) 模型没学好**：四类可分，但训练/判定把它浪费了 → 改权重/超参/判定规则即可；
- **(b) 类别不可分**：两类的**特征分布本就重叠** → 改模型无用，**必须改标签口径或补特征**。

### 4.2 诊断（第一步，必做）

```
C:\Python313\python.exe tools\eval_state_separability.py --labels tools\_scratch\state_M5_v2.csv
```

看三样：① 6 个两两组合的**时序 OOF AUC**（≈0.5 = 不可分）；② `P(pred|true)` 条件分布；
③ 行间总变差距离（<10% = 模型无法区分）。判据脚本已内置读法说明。

### 4.3 对策（按诊断结果分叉）

| 诊断 | 对策 |
|---|---|
| 关键对 AUC ≈ 0.5（**不可分**） | 改**标签口径**（`state.label.*` 阈值重标，令 oscillation 不再"稀有且模糊"）或**补特征**（`--feature-set l1` 量价/点差 6 列）；单纯重训无效 |
| AUC 均 >0.62 但 4 类 F1 低（**没学好**） | 调 `CLASS_WEIGHT_BOOST_DEFAULT`（提高 oscillation 权重）+ 超参（`num_leaves/n_estimators`）+ `--cv-splits` 复核 |

### 4.4 验收与晋升

- 验收：**macro-F1 不劣化**、`oscillation` 的 **recall 显著提升**、且 `min_conf/min_margin`
  下的 `decided` 率不失控（当前 `state.min_conf=0.35`、`state.min_margin=0.05`）；
- 前置复核：`eval_state_leadtime.py` 的漏检/误报/提前量不劣化；
- 晋升：与 §3.4 同一风险 —— 输出到 `_scratch` 验证后再放 `tools/models/`（v6），回滚 = 移除 v6。

## 7. 实施进展与发现（2026-09-19）

### 7.1 第 4 项 ✅ 已完成

见 §2.5（离线三档 A/B + 落配置 + 生效验证）。**结论**：`k_enter/k_exit/k_fade: 2→3`，
churn 收敛（S0↔S4 横跳 −28%/−36%）、停留时间由 S1_OSC 迁往 S2_TREND_INIT、模拟均值 R +29%；
代价是误报 41%→52%。**DEFAULTS 未动**（配置丢失自动回落 k=2）。

### 7.2 【重大发现】第 5 项与第 6 项**同源**，不能各自独立实施

第 5 项的第一步（重建起点事件）实测失败：

| `--min-quiet/--min-run` | 可用样本 | **正例率** | 判定 |
|---|---|---|---|
| 3 / 3 | 1377 | **72.0%** | ✗ 仍退化（目标 10~30%） |
| 10 / 5 | **113** | — | ✗ 样本 <500 门槛，`[fatal]` 退出 |

**根因（与第 6 项同一处）**：`[data] gt 趋势占比 **83.1%**` —— 4 类标签里"趋势"占 83.1%，
故"未来 5 根内出现趋势起点"近乎恒真（旧模型 `train_pos_rate=0.9493`）。
⇒ **`min_quiet/min_run` 无法在"样本≥500"与"正例率≤30%"之间同时满足**；
⇒ 想让 `rise` 分支复活，**必须先修标签口径**（= 第 6 项的范畴）。

**因此实施顺序调整为：4 → 6（标签口径 + 重训）→ 5（起点模型 + `rise_thr` 重标）**，
理由是 5 的产物（非退化起点模型）在数学上依赖 6 的产物（非趋势主导的标签）。
本调整**仅改变实施次序，不改变各项内容与验收标准**。

可用的 trend_fade 检测器"**。这与"`oscillation` 标签占 16.9% 却只预测 8.4%"完全一致，
也解释了 §1.2(c) 的"prob_oscillation 从未 >0.40"。

"未来 5 根内出现起点"近乎恒真 ⇒ 起点任务退化。**同一个标签口径问题，两处症状。**

### 7.5 复核建议：三步验证（成本递增，**先便宜后结构**）

| 步 | 动作 | 成本 | 判据（通过则继续/不通过则升级） |
|---|---|---|---|
| **① 补特征** | `train_state_model.py --feature-set l1`（base27 + 量价/点差 6 列） | 低（**不动标签**） | OOF `macro_F1` 与 `oscillation` recall 提升、且重跑可分性后关键对 AUC >0.62 |
| **② 重定标签** | 用 §7.3 的分位建议值 `--set state.label.*` 重建标签 → 重跑可分性 | 中（动标签=动状态定义） | 同上；若 AUC 仍在 0.5~0.56 ⇒ 说明阈值不是病根，进入 ③ |
| **③ 结构合并** | `{trend_init, trend_mid}` 合并为一类（总变差 0.4% = 实质同一类），FSM 的 S2/S3 相应收敛 | 高（改状态数=改契约） | `STATE_NAMES`/`market_state_log`/FSM 迁移表/前端面板同步改造 + 全量验收 |

> **诚实边界（诊断能证与不能证）**：
> 本次证明的是「**在这套特征与标签下**三者不可分」；**不能**由此断言"市场不存在这三种形态"。
> 两种可能都在：① 特征不足（→ 走 ①）；② **标签本身是错的/模糊的**（→ 走 ②）。
> 支持②的旁证：标注时 **44.7% 的 bar 被判为 ambiguous 丢弃**（`[drop_reasons] ambiguous=14507`）
> ⇒ 判据规则自身对近半数样本无把握。故**先做 ①（零标签风险）**，再决定是否动 ②。

| oscillation recall | 0.1438 | 0.1224 | **0.0988** |
| **trend_init recall** | 0.1615 | 0.1192 | **0.0000** |
| trend_mid recall | 0.4106 | 0.4716 | 0.6361 |
| trend_fade recall | 0.7931 | 0.7882 | 0.7560 |

（`trend_mid` recall 的上升是**基数效应**：该类占比 48%→65%，模型更偏向多数类 ≠ 更准。）

**表 4 根因：度量随 √N 标度，而阈值是绝对常数**

| N | er 中位 | er≥0.30 占比 | disp 中位 | disp≥0.30 占比 | er1 中位 |
|---|---|---|---|---|---|
| 1 | 1.000 | 99.8% | 0.382 | 58.9% | 0.000 |
| 3 | 0.582 | 73.1% | 0.656 | 74.9% | **1.000** |
| 6 | 0.370 | 58.6% | 0.940 | 82.0% | 0.582 |
| 12 | 0.252 | 42.1% | 1.355 | 86.9% | 0.370 |

`disp` 中位 0.382 → 1.355 = **×3.55 ≈ √12**，与随机游走标度律吻合（净位移 ∝ √N）；
而 `state.label.*` 七个阈值**全是绝对常数**（`er_osc` 0.25 / `disp_min` 0.30 …）
⇒ **每个 horizon 都必须重新标定**，现行值只对 N≈12 有效。
N=3 时 `er ≥ 0.30` 命中 **73.1%** ⇒ `trend_mid` 判据的 ER 部分近似恒真，语义退化为"残余桶"。

**★ 结构下界（代码级，与数据无关）**：`mid = i + n//2`、`path1 = _path(close[i:mid+1])`
⇒ `n=3` 时 `mid = i+1`，`path1` 只有 **2 个点** ⇒ **`er1 ≡ 1.0`**（实测中位 1.000）
⇒ `trend_init` 判据 `er1 ≤ er_osc` 永不成立（仅"相邻两根收盘价完全相同"时 `er1 = 0`，
故残留 50 条 = 0.1%）。`n=1` 更极端：`path1` 仅 1 点 ⇒ `er1 = 0`、`disp1 = 0`
⇒ **`trend_init` 恒真（72.6%）、`oscillation` 与 `trend_mid` 双双消失**。

> **不可兼得的证明**：`oscillation` 与 `trend_init` 共用同一个 `er_osc`（`er ≤ er_osc` / `er1 ≤ er_osc`）。
> 若要令 `er1 ≤ er_osc` 可满足，需 `er_osc ≥ 1.0`；此时 osc 的 ER 条件恒真
> ⇒ 而 osc 优先级在前，会吞掉 init。
> **⇒ `N ≥ 4` 是"4 类标签"的结构下界**（N=4 时 `path1` 有 3 点，`er1` 才可能 < 1）。

**结论**：**horizon 不是判别力的杠杆。** 连同 §7.7（N=12 按分位重标阈值同样失败），
现已有 **4 个 horizon 的数据点**（1 / 3 / 6 / 12）全部指向「`{oscillation, trend_init, trend_mid}`
三者不可分」。**建议保持 `state.horizon_bars = 12`，不向短调**；若确需短调，
`N=6` 是唯一"四类都健康"的短窗，但 macro_F1（0.3223）仍低于 0.3328，且**必须重标全部阈值**。

**诚实边界**：N=3/N=6 沿用 N=12 标定的阈值（未重标）⇒ 其 AUC 是"按现行配置"的读数；
但 `er1 ≡ 1.0` 使 `trend_init` 在 N=3 下**任何阈值都无法恢复**（见上证明），故结论不受此影响。
**本项为纯诊断，未改任何配置/模型/代码。**

## 9. 【方案A 判据实验】「当下定义形态」是否有前视边际？—— **不通过**（2026-09-19）

**授权**：用户选择「先跑方案 A 的 5 分钟判据实验」。

**动机（出自 §8.3 的诊断）**：唯一可学的两个量（`trend_fade` recall 0.79、波动幅度 AUC 0.6465）
有一个共同特征 —— **其未来判据与"当下可观测量"高度相关**（ADX 是慢变量、波动有聚集性）。
故提出结构性方案：**把标签从"未来定义"翻转为"过去定义"**（其余阈值逐字不动 ⇒ 是"翻转窗口"，
不是重新发明），从而让"高置信度"自然可达。

**做法**（新建 `tools/eval_causal_state_edge.py`，纯离线、零生产影响）：
镜像列取自 `build_state_memory_features`（**口径同源**），阈值逐字沿用 `state.label.*`：

```
EXHAUSTED  = adx[i] ≥ 22 ∧ (adx[i] − adx[i−12]) ≤ −3            # 镜像 adx_slope_f
           ∧ (er_trail12 ≤ 0.35 ∨ mae_trail12 ≥ 0.6)            # 镜像 (er2_f ∨ mae_f)
           ∧ ¬新极值(过去12根 vs 再往前50根)                     # 镜像 ¬new_ext_f
```

`cont_bp` 显著低于基线（t ≤ −2）；② `COMPRESSED` 的 `fwd_er` 显著低于基线（t ≤ −2）；
③ 占比 ∈ [5%, 40%]。

| 3 | EXHAUSTED | 1799 | 1.444 | 0.024 | **−6.15** | +0.25 |
| 4 | EXHAUSTED | 1235 | 1.518 | −0.040 | **−4.74** | −0.36 |

**两条附带发现（诚实记录，均不影响主结论）**：

1. **`COMPRESSED` 的"低振幅"被证实是机械效应** —— 控制波动后基本消失（桶 0：t=+0.57/−0.57）
   ⇒ 不构成独立前视信息。
2. **`EXHAUSTED` 的"未来 ATR 归一振幅更低"控制后仍成立**（3/5 桶显著，t 至 **−6.15**）
   ⇒ 方向与机制一致（趋势衰竭 → 波动收缩）。**但它与已投产的 `lgbm_vol_*`（预测波动扩张，
   AUC 0.6465）高度重叠 ⇒ 不构成新 alpha**，价值仅在于"一条规则即可廉价复现 vol 模型的一部分能力"。
3. **延续性（方向）仍不可用**：仅低波动桶弱显著（t=−2.60/−2.17），幅度仅 −0.145/−0.064 ATR。

### 9.3 旁证：当下判据 ≠ 未来判据

| | 与「未来定义 `trend_fade`」的重合率 |
|---|---|
| `EXHAUSTED`（过去定义） | **39.1%** |
| `COMPRESSED`（过去定义） | 10.9% |

⇒ **"当下已衰竭"与"未来将衰竭"是两回事**（ADX 已在下滑 ⇏ ADX 将继续下滑）。
这**机械化地解释了 §8.3 的 S4_TREND_FADE 实盘 0 胜 / 回放均值 R −0.11**：
模型能识别当下的 ADX 下滑（recall 0.79），但**这种识别没有前视价值**。

> **方法论教训**：任何"绝对 bp 比较"的结论**必须**做 ATR 归一 + 同波动桶对照，否则会把
> "当期波动小"读成"前视信号"（本实验初版就出现了 t=−6.19 的假阳性，被本节对照揪出）。

### 9.4 定案：走方案 C（状态机不提供「状态 alpha」，只保留弃权）

**但方案 C 需修正为 C′（按本次证据精确化）** —— 各"决策维度"的可达性终局如下：

| 决策维度 | 可达性 | 承载者 |
|---|---|---|
| **方向** | ❌ 不可预测 | 规则模块（`trend_direction` / 箱体边缘） |
| **波动扩张 / 幅度** | ✅ **可预测**（AUC 0.6465，漏检 91 vs 平凡规则 547，中位 +0.5 vs +12） | **已在生产**：`lgbm_vol_*` + `state.osc_vol_expand_skip` |
| 趋势相位（osc / init / mid） | ❌ 不可预测（未来时序；贝叶斯上界 50.2%） | — |
| 衰竭识别 | ⚠️ 可识别但**无前视价值**（§9.3） | 仅作观测 |
| "是否该弃权" | ⚠️ 机制已就位（§8.4），**需挂在通过验收门的头上** | 建议挂 `vol` 头（而非 4 类头） |

**⇒ 状态机的角色应从"判行情相位"重新定位为"波动路由 + 弃权"**：
低波动 → 箱体/RANGE（均值回归友好）；高波动 → 趋势（需配合起点触发器与方向）。
"4 类相位"降级为观测（或按 ③-A 收敛），不再作为开仓依据。

**下一步（唯一有证据支持的"置信度接闸门"落点）**：把 §8.4 的**校准 + conformal 机制挂到
`vol` 头**（`infer_vol_proba`）—— 它是当前唯一"够格高置信"的预测目标。
在未完成这一步之前，**不启用**任何基于 4 类 argmax 的弃权闸（§8.4 验收门三条已实测不满足）。

**本项为纯离线诊断，未改任何配置/模型/代码。** 产物：`tools/eval_causal_state_edge.py`、
`tools/_scratch/causal_state_labels.csv`。

2. **"未来波动幅度"可行，但增量有限**：T3/T4/T5 的模型 AUC **0.58~0.65**。但

3. **准确率会骗人，必须看 AUC + 单特征基线**：T5 准确率 81.5% 看似很高，但多数类基线

### 11.7 诚实边界（**必须说清**）

1. **本项不宣称"能盈利"**。路由能**减少箱体单在不利波动下的入场**，但**不改变箱体单本身的负号**——
   §8.2-D3 已测：`S1_OSC` 在**所有**置信档为负（−16.4 / −31.7bp）。⇒ 路由是"**在保留箱体单的前提下少亏**"，
   而 P0**关掉 S0/S1 箱体单**才是更大的一笔。
2. **"高波动 ⇒ 趋势"未接线**：各桶定向边际 **0.005~0.069、无单调** ⇒ **无证据支持**用波动路由过滤趋势单。
   按纪律**不做**未验证的接线。
3. **生产 vol 模型当前无校准产物** ⇒ 新键即使打开，`p_cal` 也只是原始概率、`singleton` 恒 `None`
   ⇒ 闸门**不会触发**（fail-safe）。要真正生效必须先完成 §11.6 的模型晋升。
4. 回放口径、不含成本；单品种（XAUUSD）；M5 仅 11 个月。

> **本项为机制与工具改动，全部默认关闭；未改任何生效配置，未晋升任何模型。**
> （**模型晋升与开闸见 §11.8** —— 本节 §11.7-3「生产 vol 模型当前无校准产物」已被其取代。）

### 11.8 【生产变更留痕】vol 头晋升 + 开闸（2026-09-19，用户授权"部署完成就投入生产，让运行结果证明它有价值"）

**授权原话**：「部署完成就投入生产，让运行结果证明它有价值」。

#### (1) 部署前的两个前置验证

**前置① 口径漂移归因 —— 通过（gate 的 1.13% 是伪影）**

`eval_vol_route_gate.py` 自检长期报 `不一致率 = 1.1264%`（>1% ⇒ 按工具自身纪律"结论不可信"）。归因实测：

| 检查 | 结果 |
|---|---|
| `(vol_amp_atr ≥ 3.13)` vs CSV `vol_expansion` 列 | **0.0000%**（n=68,399） |
| `OOF.y` vs CSV `vol_expansion` | **0.0000%**（n=56,995） |

⇒ **标签管线与模型产物完全自洽**；1.13% 来自 gate **自行重算 ATR**（`SF.compute_indicators` vs 标签构建器）的差异，属**重算伪影**，不是标签漂移 ⇒ §11.1 的分层结论不受影响。

**前置② 分母效应 —— 存在，且导致一条路径被撤回**

"未来振幅"以**当期 ATR** 归一 ⇒ 单调性可能只来自分母。klines 真值实测（n=56,995，脚本口径同 gate）：

| 桶 | p_cal | 归一振幅 | **绝对振幅** | **当期 ATR_t** |
|---|---|---|---|---|
| 0 | 0.175 | 2.253 | **20.909** | **12.472** |
| 1 | 0.224 | 2.550 | 16.196 | 7.660 |
| 2 | 0.297 | 2.865 | 16.400 | 6.471 |
| 3 | 0.366 | 3.148 | 16.353 | 5.622 |
| 4 | 0.466 | **3.573** | 16.402 | **4.826** |

| 判据 | Spearman | 极差 | 单调 |
|---|---|---|---|
| 归一振幅 | **+0.2902** | 1.320（1.59×） | **是** |
| **绝对振幅** | **−0.0584** | 4.714 | **否**（最低桶反而最大） |
| 当期 ATR_t | **−0.4407** | 7.646（2.58×） | 单调**递减** |

**两条结论（一条保留、一条撤回）**：

- ✅ **保留**：`vol_expansion` 的定义**本身就是 ATR 归一**，而**箱体宽度也是 ATR 归一**
  ⇒ 破界风险 ∝ `归一振幅 / box_width_atr` ⇒ **归一振幅恰是"箱体会不会被击穿"的正确量**
  ⇒ 该闸消费的量是对的，分母效应**不构成否决**。
- ❌ **撤回**：此前曾提出「vol → 动态风险归一化（按**绝对**振幅定止损/仓位）」为"唯一无需第二跳的路径"。
  实测绝对振幅 Spearman **−0.0584**、非单调、且低 p_cal 组绝对振幅**最大**（方向反了）⇒ **该路径不成立，撤回。**

**（新增待裁决项）** 阈值 `0.30` 实际拦截的是**当期 ATR 最低**的 58.5%（ATR_t 6.47/5.62/4.83 vs 放行组 12.47/7.66）
⇒ 闸门拦的是"**低波动 + 相对大位移**"的入场，与"箱体在低波动收敛时有效"的**传统认知相反**，
又与代码注释里的生产实证（箱体亏损集中在"波动放大的入场"）需对齐 ⇒ **必须由"第二跳"裁决，不能靠推理**。

#### (2) 生产变更清单（2026-09-19）

| # | 动作 | 位置/值 | 验证 |
|---|---|---|---|
| 1 | 晋升 vol 模型 | `tools/_scratch/vol_v90/lgbm_vol_M5_v90_{s0,s1,s2}.txt` + `_meta.json` → `tools/models/`（= 容器 `/app/review_models`，**bind mount `RW=false`**） | 容器内可见 4 文件 |
| 2 | 重启 signal-tower | `load_vol_models` 有**失败缓存**（`_vol_failed`）⇒ 不重启永不重试 | `Up (healthy)`，零 Traceback |

| 4 | 新增**只读**曝光点 | `state_strategy.decide` 箱体入场点：`[vol_route] … bar=<bar_id> p_cal=… singleton=… 阈值=… 结果=放行/被拦 dir=… close=… box=[lo,mid,up]` | 重启后模块正常加载（`StateStrategy config loaded`） |

**为什么曝光点必须落 `bar_id` + 箱体三线**：闸门一旦开启，"被拦"候选**不产生订单** ⇒ 事后**无从结算**。
不记这两项，"运行结果能否证明价值"在结构上**无法回答**。有了 `(bar_id, dir, close, box 三线)`
即可**离线重放**该候选的 TP（`tp=mid(0.50)`，与生产一致）与破界结局 ⇒ 得到**反事实 R**。

#### (3) 预注册判定规则（**在任何前向数据到达之前写定**）

> 纪律：不预注册就会变成"事后挑到支持自己的子集"。以下判据**不得事后修改**。

**主判据（反事实对照）**：`[vol_route]` 中**被拦候选的反事实 R** vs **放行候选的实际 R**。
- 反事实口径（固定）：自 `bar_id` 起 **12 根**内，先触**箱体中值**（胜）还是先触**箱体对侧边界**（负）。
- 判定门槛：**被拦组反事实 R 的 95% CI 上沿 < 放行组 R 的下沿** ⇒ 闸门有价值；
  **两 CI 重叠 ⇒ 不成立**（继续观察，**不得下结论**）。
- 样本要求：**被拦 ≥ 20 且 放行 ≥ 20**；观测窗 **≥ 2 周**。

**副判据（相对基线）**：放行组相对「开闸前 14 天箱体单基线」的 R 改善（样本要求同上）。

**联合规则**：主判据不成立 ⇒ **回滚**（`osc_skip_prob = -1.0`），**无论副判据如何**。

### 11.9 【矫正】训练工具正确化 + 晋升纪律（2026-09-19，用户授权"现在把 4 和 5 一起做"）

**触发**：ML 实践审计（"有没有正确使用 LightGBM"）发现四处"错或没做"。本节修其中 **P1 两项**：
**验收有效性**与**晋升纪律**。另两项（目标定义、可归因性）见 §12。

#### (1) 缺陷①：校准验收门**无效** —— ECE 在拟合集上测

`fit_confidence_calibrator` / `fit_binary_prob_calibrator` 在 **OOF 上拟合** isotonic 后，
**在同一批 OOF 上**报告 `ece_cal`；而 isotonic 能**精确拟合它自己见过的样本**
⇒ **`ece_cal = 0.0000` 是构造性结果，不含泛化信息**。
（⇒ §8.4 / §11.1 引用它作为"校准良好"的证据**无效**。）

**修法**：新增 `_cross_fitted_ece()` —— 按**时间顺序**切 K 折（**不洗牌**：洗牌会把未来折信息
带入过去折的校准器），每折用其余折拟合、在该折上评估，样本数加权汇总 ⇒ **样本外 ECE**，
落 meta 的 `ece_cal_cv`。读数纪律写进 docstring：**验收只看 `ece_cal_cv`**。

**实测（`--target vol`，`gap=12`，3 折冒烟）**：
`ECE 0.0592 → 样本内 0.0000 → **交叉拟合 0.0311**`
⇒ 校准**确实不错**（0.0311 < 0.05），但**不再是"完美"的幻觉**。

#### (2) 缺陷②：折边界**标签重叠**（无 purge/embargo）

标签是**前瞻**的（`label_metrics(i)` 用 `close[i+1 : i+horizon]`），而 `TimeSeriesSplit`
默认让两折**首尾相接** ⇒ 训练折末尾 `horizon` 根的标签用到了验证折开头 `horizon` 根的价格。

**修法**：`oof_time_series(..., gap=)` → `TimeSeriesSplit(n_splits, gap=)`；
`train_state_model --gap`（默认 **12** = `state.horizon_bars`）；`train_onset_model --gap`
（默认 **= lead**；`vol` 一律 12）。

**实测影响**：vol 头 OOF AUC **0.6452 → 0.6365**（消除泄漏后略降，符合预期）。

#### (3) 缺陷③：**训练即上线** —— 默认 `--outdir` 就是生产目录

`MODELS_DIR_DEFAULT = <tools>/models`，而该目录是容器 `/app/review_models` 的 **bind mount 源**
⇒ 不带 `--outdir` 训练 = 产物被 `max(version)` **立刻采纳**（无人工确认）。

**修法（复用既有规范，不另立）**：`auto_retrain.py` **早有**版本四态
（`MODEL_STAGING_DIR = MODELS_DIR/_staging`，注释：TRAIN → ACCEPT → promote），
但三个训练器里**只有 quality 头遵守**。现统一：

```
MODELS_DIR_PROD    = <tools>/models
MODELS_DIR_DEFAULT = <tools>/models/_staging
```

选**子目录**而非并列目录的理由：`state_infer._discover` 是**非递归 glob**
⇒ `_staging/` 天然不被发现（**零加载逻辑改动**）。另加**守卫**：`--outdir` 显式指向
生产目录时打 `[warn]`。

#### (4) 缺陷④：**隐式选版**（`max(version)`）

三处选版一律 `best = max(versions)` ⇒ 「把文件放进模型目录」即等于上线。

**修法**：新增 `_pick_version(target, tf, versions)` + 三个配置键
（缺键 ⇒ 沿用 `max`，**零行为变化**）：
`state.model_version.{tf}` / `state.onset_model_version.{tf}` / `state.vol_model_version.{tf}`
（容忍 `2` 与 `v2` 两种写法）。
**钉值不存在 ⇒ 回落 `max` 并打 WARNING**（不拒载：一次配置笔误不应让推理层停摆）。

#### (5) 验证（实测）

| 项 | 结果 |
|---|---|
| `MODELS_DIR_PROD` / `DEFAULT` | `tools\models` / `**tools\models\_staging**` ✓ |
| 配置热载 | `pinned={}`（**零行为变化**）+ 容器 `healthy`、零 Traceback |
| 版本钉 A 无钉 | `state → v5`（= max，既有行为） |
| 版本钉 B 钉 v3 | `state → **v3**`（真的切换） |
| 版本钉 C 钉 v7（不存在） | `state → v5` + WARNING `不在可用版本 [1,2,3,5] 中 → 回落 v5` |
| 版本钉 D | `vol → v90`、`onset → v1` |
| `py_compile` / lint | 三文件全过 |

#### (6) 回滚（秒级）

- **版本钉**：删配置键即回 `max(version)`。
- **训练工具**：`--outdir` 显式指回 `tools/models`（会打 `[warn]`）。
- **`state_infer`**：`git checkout` + 重启。

#### (7) 诚实边界

1. **`gap` 会改变所有历史 OOF 读数** ⇒ 此前记录的 AUC / macro-F1 均为"**含泄漏**"口径，
   **不可与修复后直接比较**。
2. `ece_cal_cv` 是 K 折时间切分的估计；**折数少时方差大**（冒烟用 3 折 ⇒ 0.0311 仅供参考）。
3. **版本钉只解决"选哪一版可见"，不解决"何时晋升"** —— 晋升仍是人工动作。
4. **未改任何生效配置**（`pinned={}`、`osc_skip_prob` 未动）；本轮仅一次重启。
