# 方案：让 HEXP 站到正确方向（行情判断修复设计稿）

> 2026-09-12（周六）。承接《机制深析：上涨做空反转不做空》。目标：解决"永远站在错误一边"——涨中做空、转跌抄底、趋势做空路径关闭。
> **核心判断**：修复不需要重写引擎。HEXP 已内置三类"正确方向"机制，全部被配置关在 `shadow/off`；另有 `micro_state` 微观状态机（Phase 0 shadow）可当实盘闸门。本方案 = **激活 + 调参 + 接一扇门**，分 4 阶段，Phase 0 纯观测零风险。

---

## 0. 设计原则：体制自适应（regime-adaptive）

| 市况 | 正确动作 | 错误动作（现状） |
|---|---|---|
| 确认趋势 UP | 跟多（BUY） | NEUTRAL-fade 摸顶 SELL（12:36） |
| 确认趋势 DOWN | 跟空（SELL） | 均值回归抄底 BUY（17:15）/ 无单 |
| 趋势衰竭/反转 | 等确认/反向 | 还在 fade |
| 震荡 RANGE | 边界均值回归（R:R≥1.2） | 任意 fade |

关键：**趋势跟随必须对双向（含做空）生效**，且均值回归只在"证明衰竭"时做，不在"价格到了高低位"就做。

---

## 1. 已内置但被关掉的"正确方向"机制（file:line）

| 机制 | 位置 | 现状 | 作用 |
|---|---|---|---|
| 趋势优先硬拦 | `hexp_engine.py:1554-1574`（`hexp.trend_priority_mode`） | 默认 `shadow`（只打日志不拦） | 确认趋势时拦逆势单 |
| 方向头强制翻向 | `hexp_engine.py:1521-1552`（`hexp.dir_lm_flip_enabled`） | 默认 `False` | LightGBM 方向头实时反向时翻向，专治滞后 |
| 方向迟滞 TTL | `hexp_engine.py:1484`（`hexp.direction_hysteresis_ttl_bars`） | 默认 `0`（关） | B4 补丁：方向粘死超 N 根强制翻 |
| 微观状态机 HMTS | `micro_state.py`（5 态） | Phase 0 shadow（`:1-9`） | 区分 TREND_ACCEL/PULLBACK/EXHAUST/REVERSAL |
| 精准买点分 | `precision_entry.py`（含 `min_rr=1.2`） | Phase 0 shadow（`:6-8`） | 方向对齐+微观结构+R:R 硬门槛 |

→ **要做的不是写新逻辑，是把这些接进实盘并调参。**

## 2. 分阶段方案

### Phase 0 — 影子验证（纯观测，零风险，先做）
- 在 scheduler 里**保持** micro_state + precision_entry 为 shadow，但把它们的判定结果落库（已有 `trend_governance` 观测出口 `hexp_engine.py:1576`）。
- 用 09-11 + 一个下跌日回放：统计 HMTS 状态机对每个 09-11 信号会判什么，对照实际盈亏。
  - 预期：12:36 SELL（创新高）→ HMTS=TREND_ACCEL UP / REVERSAL → 若接门会**拦**；17:15 BUY（回落）→ HMTS=TREND_ACCEL DOWN → 会**拦**；18:50 SELL（下跌中）→ HMTS=TREND_ACCEL DOWN → 会**放（且正确）**。
- 验证指标：shadow 门对"涨中摸顶空/转跌抄底多"的拦截率、且不误杀真正的好单（RANGE 边界单）。**通过才进 Phase 1/2。**

### Phase 1 — 激活趋势跟随（含做空）
- `hexp.trend_priority_mode: "shadow" → "on"`（`hexp_engine.py:328`）：确认趋势时**真拦逆势单**。
- 让趋势态能被实时识别（否则 `_tp_confirmed` 永不真，拦不住跌市）：
  - 下调 `hexp.trend_start.hold_bars` 90→~30（`:342`）、`bbw_max` 20→~25、保留 `trend_confirm_include_h1=True`（`:329`）+ `h1_ind_enabled=True`（`:330`）让 H1 实时方向参与。
  - **对称化** `hexp_engine.py:1554` 收口逻辑：确认 TREND_DOWN 时显式 **BLOCK 均值回归 BUY（抄底）并 PASS SELL（跟空）**，而非仅收口反向。
- 风险：趋势检测变灵敏会减交易数、震荡市可能误拦 → 必须 canary（先 1 账户/影子对照）。

### Phase 2 — 接 HMTS + precision_entry 为实盘闸门（治本）
- 在 `scheduler.py:1961-2013`（HMTS 已计算处）/ `:1997-2000`（precision_entry 已计算处）**前插一道 live 校验门**，规则：
  - `micro_state == TREND_ACCEL` 且 `direction==DOWN` + 信号 `BUY` → **BLOCK**（禁转跌抄底）。
  - `micro_state == TREND_ACCEL` 且 `direction==DOWN` + 信号 `SELL` → **ALLOW**（趋势跟空——补全缺失的做空路径）。
  - `micro_state == TREND_ACCEL` 且 `direction==UP` + 信号 `SELL`（摸顶）→ **BLOCK**。
  - `micro_state == TREND_EXHAUST` → **BLOCK**（等反转确认）。
  - `micro_state == REVERSAL`（H1 确认反向突破）→ **ALLOW 翻向**。
  - `micro_state == TREND_PULLBACK` → **ALLOW**（核心买点）。
  - `precision_entry._risk_reward` 的 `min_rr=1.2`（`precision_entry.py:44`）作为**硬门槛**，R:R 不足直接降权/拦。
- 这一道门同时治：① 涨中摸顶空、② 转跌抄底多、③ 趋势做空路径缺失、④ R:R 失控（缺陷 E）。

### Phase 3 — 去滞后（可选，慎重）
- 方案 A（推荐，安全）：降低 `verdict` 中高周期（D1/H1/H4）权重（`hexp_engine.py:1620-1706` 的 `weight_*`），让 M5 实时极值（pos_in_range/rsi/ma 斜率）主导 → 引擎不再交易"上一根腿"。
- 方案 B（需先验证）：`hexp.dir_lm_flip_enabled: True`（`hexp_engine.py:1526`）让 LightGBM 方向头强制翻向。**注意**：dir_lm 当前 `ai.mode=decoupled`、仅观测，其精度未验证（c_ai AUC 0.513 无正向贡献）。**必须先离线验证 dir_lm 在下跌日的方向准确率**，否则会引入新错误。建议 Phase 3 走方案 A。

### Phase 4 — 方向迟滞清理
- `hexp.direction_hysteresis_ttl_bars: 0 → N`（如 20）（`hexp_engine.py:1484`）：趋势结束后方向不在旧向粘死，及时翻向。

## 3. 改造前后对照（09-11 三笔）

| 时间 | 行情 | 现状动作 | 改造后（HMTS 闸门） | 结果变化 |
|---|---|---|---|---|
| 12:36 | 涨中创高 | NEUTRAL/TREND_FADE SELL −19.8 | TREND_ACCEL UP → BLOCK 摸顶空 | 避免打损 |
| 17:15 | 峰值回落 | NEUTRAL BUY 抄底 −9.2 | TREND_ACCEL DOWN → BLOCK 抄底多 | 避免打损 |
| 18:50 | 继续下跌 | NEUTRAL SELL（迟到小损） | TREND_ACCEL DOWN → ALLOW 跟空 | 正确做空、吃下跌段 |

→ 同一波"涨→顶→跌"，改造后**不在涨中做空、不在顶后抄多、在跌中及时做空**。

## 4. 执行顺序与风险

1. **Phase 0（必做，零风险）**：影子回放 09-11 + 下跌日，确认 HMTS 拦截正确率与误杀率。
2. Phase 1（低风险，需 canary）：开 `trend_priority_mode=on` + 趋势检测调灵敏。
3. Phase 2（中风险，治本）：接 HMTS/precision_entry live 门，含 `min_rr=1.2` 硬门槛。
4. Phase 3（方案 A 安全 / 方案 B 需先验证）：去高周期滞后权重。
5. Phase 4（低风险）：方向迟滞 TTL。

**总原则**：每一阶段先在 1 个账户/影子对照跑 ≥3 天 canary，对照基线（实现 RR 0.242→≥0.8、先碰 SL 83%→<50%、SELL/BUY 不再极端 34/2）再全量。

## 6. Phase 0 实测修正（2026-09-12，已跑通，详见《Phase0_验证_双向样本影子回放》）

**用真实引擎模块离线回放 99 笔（09-11 涨 36 + 09-10 跌 63），对照实际盈亏，推翻了原 Phase 2 的朴素假设：**

1. **亏损主力不是摸顶单，是 NEUTRAL 均值回归单**：引擎自己在交易时刻判 `regime=NEUTRAL` 占 **71.7%（71 笔，合计 −124.47）**；HMTS 微观状态 `RANGE` 占 **88.9%（89 笔）**。→ M5 微观几乎从来看不到趋势，不能当方向权威。
2. **方向对齐网关(B) 双刃**：09-11 干净拦下两笔 12:52 摸顶 SELL（−41.9，0 误杀，验证"涨中摸顶"病理）；但 09-10 下跌日**误杀 3 笔盈利 SELL（+3.55/+3.03）**——把下跌日回踩做空当成"涨中摸顶"拦掉。**单用会伤下跌日，不可直接上线。**
3. **"转跌抄底多"模式样本内 0 笔**：引擎下跌日几乎不开 BUY（09-10 仅 7/63），且 HMTS 在 BUY 时刻未看到 `TREND_ACCEL DOWN`（滞后）。站错边在下跌日表现为"该跟空没跟上/该翻向粘旧偏置"。

**→ 方案修正（治本顺序调整）**：
- **P1 升为主线（必做）**：激活 `trend_priority_mode=on` + 高周期实时趋势参与，确认趋势时 **HEXP 由均值回归切换为趋势跟随**，直接砍 −124 的 NEUTRAL 主力亏损池（而非只拦少数摸顶单）。
- **P2 降为确认层**：HMTS 只拦最清晰的 `TREND_EXHAUST` 接刀 + `TREND_ACCEL UP+SELL` 摸顶，且**须 H1 趋势门控**（仅 H1 非确认下跌时才拦 SELL），消除下跌日误杀。
- P3/P4 不变。
- 任何方向对齐硬拦**必须 H1 门控**，否则下跌日误杀盈利 SELL（实测 6.8% 误杀率）。
