## 二、正确且已贯通的部分（确认无误）

### A1. 激活/路由链路（与文档"独立信号源 + 与手动/双源切换激活"一致）
- 前端 `Mode.tsx` Tab2 → `PUT /api/cosource/config` 写 `signal.active_model='hexp'` + `PUT /api/signal-tower/mode(co_source 自动路由)` + 触发 `activate`。
- `scheduler._detect_active_model` 经 `config_provider` 读 `signal.active_model='hexp'` → 命中 `MECHANISM_PROFILES['hexp']` → 每周期 `_mechanism_profile` 解析 `profile["engine"]` 指向 `HexpEngine` → `_symbol_loop` Step 4a 调 `engine().produce()`。✅
- `HexpEngine` 默认构造参数 `signal_mode_default="hexp"`、`active_model_default="hexp"`，且 `apply()` 内部 `_get_active_model()` 返回非 hexp 时原样返回（不污染其他模型）。✅

### A2. 后端 API（禁硬编码 ✓）
- `hexp.py` 的 `create_hexp_router` 注册 `/api/hexp/*`，所有 PATCH 经 `config_provider.set` **双写 PG + Redis + PUB**，`PATHS` 为 `HEXP_KEYS` 子集，`_hexp_get` 经 `config_provider.get` 读取。✅
- 配置键全量定义在 `HEXP_KEYS`（含中文 friendly label / 分组 / 默认值），无硬编码散落（除少数策略常量，见 BUG-15）。

### A3. HP-Score 广义均值结构（文档 2.1 ✓）
```python
# 文档: HP-Score = (Σ w_i·|f_i|^k)^(1/k) × sign(Σ w_i·f_i)
hp_strength = pow_sum ** (1.0/k) if pow_sum > 0 else 0.0   # (Σ w_i·|f_i|^k)^(1/k)
direction   = "BUY" if dir_sum > 0 else "SELL" if dir_sum < 0 else "NO_TRADE"
```
方向与幂次结构正确。✅

### A4. NO_TRADE 判定 / 评分卡分级 / 等级阈值（文档 6.1 / 6.2 ✓）
- `dir_sum<0.01 and max|f|<dmin(0.20)` → NO_TRADE，与文档 6.1 step1 一致。
- 评分卡权重 `25/20/20/15/10/10`（共振/状态/入场/位置/波动/时段）与文档 6.2 一致。
- S/A/B/C/红灯 分级阈值与文档逐字一致（含 `hp_100<30→红灯`）。✅

### A5. 6 维因子（ADX/ER/MA/BBW/Hurst/RSI）方向极性总体正确
- ADX：`f_adx = adx_norm * di_sign`（文档 +DI>-DI 为正，×adx_norm）。✅
- ER：`f_er = er_norm * er_sign`（方向与价格位移一致）。✅
- BBW：`f_bbw = bbw_pct/100 * bbw_sign`（方向随突破方向）。✅
- RSI：趋势/震荡两模式映射与文档 4.1 阈值一致。✅
- MM：加权幂律动量 `w_i=(i+1)^(-α)`，新近棒权重最大，与文档 5.2 一致。✅

## 三、BUG 清单（按严重度）

### BUG-1 ❌【公式级·P0】k 自适应幂指数双重计数，背离文档 2.2
**文档 2.2 原文**：
> k_base = 1.5（中性基准）
> k = k_base × (1 + α × (ADX_norm − 0.5) + β × (BBW_pct − 50)/100)
> 结果范围：强趋势 k=1.8~2.5 / 震荡 k=0.5~0.8 / 转换 k=1.0 / 衰竭 k=2.0~3.0

**代码实际**（`hexp_engine.py` 自适应 k 块）：
```python
k_state_key = {
    "TREND_UP": "hexp.k.state_trend", "TREND_DOWN": "hexp.k.state_trend",
    "RANGE": "hexp.k.state_range", "TRANSITION": "hexp.k.state_transition",
}.get(state, "hexp.k.base")
k_base = cfg[k_state_key]          # ← 用体制 k 值(2.0/0.65/1.0)覆盖文档的 1.5
k = k_base * (1.0 + cfg["hexp.k.alpha"] * (adx_norm - 0.5)
              + cfg["hexp.k.beta"] * (pf["_bbw_pct"] - 50.0) / 100.0)
k = min(hexp_k_max, max(hexp_k_min, k))
```
**后果（双重计数）**：
- 强趋势：`k = 2.0 × (1 + 0.8(ADX/50−0.5) + 0.4(BBW−50)/100)`，ADX/BBW 偏高时恒逼近上限 **3.0**（文档要 1.8–2.5）。
- 震荡：`k = 0.65 × 公式`，在 ADX/BBW 偏高时可冲到 **1.04**（文档要 0.5–0.8）。
- `hexp.k.base=1.5` 在 `HEXP_KEYS`/`_DEFAULTS` 中暴露但**从未被用作 k 基值 → 死配置**。

**修复**：`k_base = cfg["hexp.k.base"]`（=1.5），删除 state k 替换；或若确要 state-driven，则去掉之后的自适应乘子（二选一，不可叠加）。

### BUG-2 ❌【逻辑级·P0】Step 4b 无条件套用 co_source，hexp 激活且 co.v2_enabled=True 时被 v2 覆盖
**代码**（`scheduler.py` 约 1402–1406 区域）：
```python
if self._co_source is not None:
    _legacy = await self._co_source.apply(score_result, indicators, regime_result, ...)
    if _v2_enabled and _ms is not None:              # ← 仅受 co.v2_enabled 门控
        score_result = await self._co_source.apply_v2(_legacy, indicators, ...)
    else:
        score_result = _legacy
```
该块**没有 `if active_model == "co_source"` 守卫**。
- `apply()` 内部有 active 检查（非 co_source 时 return 原样）→ 对 hexp 不变，OK。
- 但 `apply_v2` 仅受 `co.v2_enabled` 门控，与 `active_model` 无关；其内部用 `micro_state`/`precision_entry` **重新裁决 direction/grade/threshold_passed**。一旦用户启用双源 v2（`co.v2_enabled=True`）而主模型切到 hexp，`apply_v2` 会用双源 v2 逻辑**覆盖 hexp 的决策**，使和乘幂丧失独立性——直接违背文档"独立信号源 + 切换激活"要求。

代码注释（1403–1405）声称"仅当 signal.active_model == 'co_source' 时 CoSourceEngine.apply() 才施加过滤"，这只对 `apply()` 成立，对 `apply_v2` 不成立，注释具有误导性。

**修复**：用 `if active_model == "co_source":` 包裹整个 Step 4b；hexp 走自身 `produce()` + 内部门控（目前仅评分卡 + MTF 铁律，见 BUG-13）。

### BUG-3 ❌【缺失级·P0】体制感知权重方案（文档 4.2）完全未实现
**文档 4.2** 要求按状态切换因子权重 w_i：
- TREND：ADX0.30 / ER0.25 / MA0.22 / BBW0.13 / Hurst0.10
- RANGE：ADX0.10 / ER0.15 / MA0.10 / BBW0.30 / Hurst0.15 / RSI0.20
- TREND_FADE：ADX0.35 / ER0.20 / MA0.20 / BBW0.10 / Hurst0.15

**代码**（`produce()`）：HP-Score 始终用**固定** base 权重 `hexp.factor.*_weight = 25/25/20/15/10/5`（归一化），**不随状态切换**。RSI 固定权重仅 `5/115≈4.3%`，而文档 RANGE 体制下 RSI 应占 **20%**。

**后果**：RSI 在震荡体制下被严重低估，ADX 在各类体制等权——与文档"体制感知"设计意图相反。整个 4.2 子系统缺失。

**修复**：在 `produce()` 中按 `period_states[primary]` 选权重表（新增 `hexp.weight.trend.*` / `hexp.weight.range.*` / `hexp.weight.fade.*` 配置，或硬编码三套默认值并在 load_config 读取）。

### BUG-5 ⚠️【公式级·P1】Hurst 因子方向语义与文档相反
**文档 4.1**：H>0.5 → 趋势持续(+)（绝对方向，与 DI 无关）；H<0.5 → 均值回归(−)。
**代码**：
```python
f_hurst = h_norm * di_sign * (1 if h >= 0.5 else -1)
```
当 H>0.5（趋势持续）且 DI 指向下跌（`di_sign=-1`）时，`f_hurst` 为负（利空），与文档"H>0.5 一律 +"冲突。代码把 Hurst 解释成"延续 DI 方向"，文档则把它当作独立的趋势/回归极性。

**说明**：从"趋势延续当前方向"的直觉看，代码版更合理；但**与文档字面相反**，属文档与实现需对齐的开放问题。建议明确选其一并文档化（若改代码，去掉 `di_sign`）。

### BUG-6 ⚠️【公式级·P1】多周期共振 verdict 归一化与文档不符
**文档 6.1**：`verdict = D1×0.25 + H4×0.35 + H1×0.25`（加权**和**，值域≈[-0.85,0.85]，M5 不参与）。
**代码**：对参与周期按 `hexp.mtf.weight_<p>` 加权后**再除以权重和 wsum_r**（归一化为 [-1,1]）。

**后果**：verdict 量纲改变 → `hexp.mtf.long_threshold=0.5`、`mtf.iron_rule`、`共振分|verdict|×100` 的实际触发点与文档不同（边界值阈值整体偏移）。

**修复**：改为加权求和（不除以权重和），或显式配置"是否归一化"开关并同步下游阈值。

---

### BUG-7 ⚠️【公式级·P2】MA 因子斜率贡献范围与文档不符
**文档 4.1**：EMA20 回归斜率贡献 **±40**（加到 50 基准上）。
**代码**：`slope_norm_bp=3.0`，`f_slope = clamp(slope_norm/slope_norm_bp*50, -50, 50)` → 斜率贡献 **±50**，且 3bp/bar 即打满。

**后果**：斜率项对 MA 因子的贡献比文档大 25%，且满量程基准 3bp/bar 为代码臆造（文档未给）。

**修复**：改为 ±40 上限，并显式配置斜率满量程 bp（需补充到文档或配置）。

### BUG-8 ⚠️【缺失级·P1】多周期共振→仓位/许可矩阵（文档 7.2）未实现
**文档 7.2** 给出详细裁决表：H4 趋势 + H1 趋势 + M5 同向 → 满仓；H4/H1 任一反向或 TRANSITION → 降仓/观望等。
**代码**（`produce()`）：仅实现"TRANSITION → lot_mult×0.5"，其余（满仓/标准/半仓/观望）规则未实现。

**后果**：缺失"多周期共振满仓""反向观望"等关键风控分支，实际只有"降一半"一种行为。

### BUG-9 ⚠️【缺失级·P2】M1 微结构三类信号（文档 5.3：加速/衰竭/反转）未实现
**文档 5.3** 定义三种信号：MM 连续 3 根 M1 单调增大超阈值（加速）、MM 从高位快速下降（衰竭）、MM 从负转正（反转）。
**代码**：仅实现单一 `f_mm = tanh(加权动量/scale)` 作为第 7 因子 + 加速 boost（`mm_rising`）。三类命名信号未实现。

### BUG-10 ⚠️【缺失级·P2】执行层（第 8 章 回踩 A/突破 B 双模式、动态 SL/TP、跟踪止损）未实现
**代码**：`produce()` 仅输出 `ai_sl_mult`/`ai_tp_mult`/lot 倍率与 `co_band` 壳子；无回踩/突破择时、无具体 SL/TP 价位、无 chandelier/移动止损逻辑。
该章原规划为 P3，但属与"和乘幂下单"直接相关的链路缺口——目前 hexp 信号经 `risk_engine` 走通用下单，SL/TP 由信号塔 `place_mt5_order` + 老 co_source 的 `close` 配置兜底，与和乘幂自身策略意图脱节。

### BUG-11 ⚠️【低·文档偏差】H1 迟滞状态机缺 ADX≥22 与突破事件条件
**文档 7.1**：进入趋势需 TrendScore≥60 + 确认 confirm_bars + 突破事件 + ADX≥22。
**代码**（`_HysteresisState.update`）：仅判 `trend_score>=enter and direction!=0`，缺 ADX≥22 与突破事件。H1 可能在 ADX 低时过早进入趋势态。

### BUG-12 ⚠️【低·文档偏差】M5 轻量状态机与文档 AND 条件不符
**文档 7.1**：M5 轻量状态 = (EMA20>EMA50) **AND** (+DI>−DI) → BULLISH；否则 BEARISH；否则 NEUTRAL。
**代码** M5 轻量态用 `pdir = ma_dir(with di fallback)`：ma_dir 与 di_dir **任一**即可（fallback 逻辑），并非严格 AND。可能把"EMA 多头但 DI 空头"判为 BULLISH，文档要求严格 AND。

### BUG-13 ⚠️【低·文档偏差】第 9 章 专属闸门未实现
文档 9.1 三道闸门：F1 MACD 背离 ×0.20、F3 事件窗口 ×0.25、点差>0.35 不交易、连胜冷却、日亏损熔断。
**代码**（`produce()`）：无这些闸门，仅评分卡 pass + MTF 铁律。spread/F1–F5/熔断等依赖下游 `risk_engine` 通用规则，和乘幂自身 9 章专属闸门缺失。

### BUG-14 ⚠️【低】`_mm_signal` 归一化与文档公式小差异
**文档 5.2**：`MM(t)=Σ w_i·r(t-i)`（未归一化加权**和**）。
**代码**：除以 `sum(weights)`（归一化）。因外层 `tanh`，幅度被 `hexp.mm.scale` 吸收，功能等价但偏离公式字面。建议文档注明。

### BUG-16 ❌【配置热重载·P0】HexpEngine.load_config 仅在 __init__ 调用一次
若用户经 API 调整 `hexp.k.alpha` / `hexp.mtf.weight_*` 等，**必须重启调度器**才生效（co_source/scoring 已有 60s 热重载，hexp 没有）。文档"保存即热生效"承诺未达成。

**修复**：在 scheduler 主循环加 `self._hexp.load_config()` 周期调用（仿 `_refresh_deepseek_config` 节流模式），或暴露 reload 端点。

---

### BUG-17 ⚠️【鲁棒性·P2】produce 对缺失数据防御不足，KeyError 会被静默吞为停摆
`produce()` 直接访问 `period_data[primary]["adx"]` 等；若某周期 `IndicatorsResult` 未计算该键会 KeyError。`produce` 被 `_symbol_loop` 的 `try/except` 包裹，异常会被吞为 "Symbol loop error" 并 `continue`（历史上有 co_source 同类 bug），导致该 symbol 静默停摆。

**修复**：对 `period_data` 缺失键做 `or 0` / 默认值防御，避免 KeyError 空转。

## 五、审计方法说明
