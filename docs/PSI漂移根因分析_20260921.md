## 0. 结论（TL;DR）

**本次 PSI 重度漂移是"数据供给断裂"导致的假阳性告警，不是真实的行情 regime 变化，也不是基准基线过时。**

根因链：
1. **2026-09-19 ~16:08** 信号塔（signal-tower）推理/下单链路中断约 8 小时（`inference_log` 当日仅 559 行，16:08 后归零；同窗口持仓开仓数 = 0 → 真实停摆，非仅日志断写）。
2. **2026-09-20 行情数据（klines）系统性断裂**：M5 由 288 根/日跌至 **24 根**，M1 1440→120，H1 24→2，M30 48→4（全周期同时崩）。09-21 仅部分恢复（M5=101）。
3. **信号塔推理/下单循环以定时（每 3–5s）方式继续运行**，但底层 klines 已近乎空缺 → 在残缺/冻结的 klines 上计算特征 → 波动率/离散度类特征（ATR、BBW、`atr_pct`、`spread_atr`、`bbw_pct`）被系统性扭曲 → 20+ 个特征 PSI 同步虚高（eval 口径 max≈2.37，raw 最高 8.28≈理论极值）。
4. **真实 XAUUSD 价格全程平稳、区间震荡（4340–4390）**，`dev_z` 围绕 EMA60 正常摆动（−5~+15），无任何趋势破位。原始 `spread` 每日中位数恒为 20 → `spread_atr` 的虚高纯属 ATR 分母（由稀疏 klines 算出）失真。

判定：**输入数据坏了，特征分布跟着坏，PSI 跟着响。价格没动 = 非真实 regime 漂移。**

## 2. 根因推导（区分事实 / 推测）

**事实（已证实）：**
- 09-19 16:08 信号塔停摆 ~8h（inference_log + 持仓开仓同步归零）。
- 09-20 klines 全周期断裂（24/120/2/4 根），09-21 部分恢复。
- 同窗口 inference_log 仍有 1,730/8,590 行 → 推理/下单循环在坏数据上继续跑。
- 价格平稳、spread 恒定、dev_z 无破位 → 无真实 regime 漂移。
- 漂移集中在波动率/离散度类特征且同步发生 → 单输入源（klines）损坏的特征指纹。
- 监控计算正确（重放 pinned 基准 vs post 得 max≈5.2/20 漂移，与报告一致）。

**高置信推测（机制）：**
- `atr_pct / spread_atr / bbw_pct` 虚高由"ATR/带宽等分母在稀疏 klines 上算出极小值 → 比率类特征爆炸"导致；09-21 部分回正是 klines 恢复后分母回归。
- `verdict` 09-21 跳变是 regime 分类器看到失真特征后的输出漂移，非市场本身变天。

**明确排除（非本次成因）：**
1. ❌ 已知豁免特征假象（`event_proximity_min` 等）——本次漂移特征不在豁免清单。
2. ❌ 基准基线过时（stale baseline）——基准 09-18 健康，漂移全在 post 侧。
3. ❌ 真实行情 regime 切换——价格平稳、方向类特征仅在噪声带内偏移、spread 未变。
4. ❌ 监控代码 bug——重放验证计算正确。

## 3. 风险（须警示，非仅技术债）

1. **系统在坏数据上实际开了仓**：持仓 `max(open_time)=2026-09-21 08:10`、`total=2697`，说明 09-20 00:15 之后信号塔恢复期间**在失真特征下产生了新持仓**（09-19 16:00–09-20 00:00 停摆段开仓=0，恢复段有开仓）。这些单的入场依据可能失真 → **潜在劣质/错误持仓**，建议核查 09-20~09-21 开仓单的盈亏与信号质量。
2. **若自动重训/换基被触发**：会把坏数据分布 bake 进基线或模型 → 此后真实漂移不可见，且模型在坏样本上重训 → 模型退化。当前未确认 auto_retrain 是否处于启用并会自动动作（需核 `auto_retrain.py` 调度与 `ai.*` 开关）。
3. **监控信任度受损**：假阳性 PSI 会训练运维"狼来了"，未来真实漂移被忽略。

## 4. 修复建议（分级，均待授权后落地）

**P0 — 立即（不改模型/基线）：**
- 对本次 PSI 告警**定性为假阳性**，暂不触发重训/换基。先确认 auto_retrain 自动动作是否被禁用；若启用，临时冻结其 PSI→重训联动，直到数据恢复。
- 核查并修复 **09-19/09-20 的 klines 采集/中继故障**（collector 容器/MT5 桥连接/网络）——这是事故真源，独立于 PSI。

**P1 — 防线（防"坏数据上推理/下单"复发）：**
- 信号塔增加**数据新鲜度闸门**：若最新 klines 年龄 > N 分钟（或近窗口 bar 数 < 阈值），**暂停推理与下单**并打 `DATA_STALE` 告警，而非在冻结/残缺 klines 上算特征。这是本次核心缺陷——系统本应在 09-19 16:08 起就停，而不是带病运行。
- 监控侧：PSI 报告在检测到数据新鲜度违例的时段**自动豁免/标注**，并把"波动率类特征全体同步漂移"识别为 feed-health 信号，与"模型 drift"分列。

**P2 — 恢复（数据恢复后）：**
- 待 klines 连续 24h 恢复正常 bar 数、inference_log 分布回稳后，再执行 `--build-live-baseline` **重新 re-pin 基线**；PSI 应随健康数据自然回落。
- 复盘 09-20~09-21 在失真特征期间产生的持仓，评估是否需人工平仓/风控复核。

**P3 — 复核（确认假设）：**
- 确认 `auto_retrain` 当前是否启用自动重训（避免误触发）。
- 确认 09-19 16:08 信号塔停摆与 09-20 klines 崩是否同一根因（container crash / MT5 断连 / 磁盘）。
